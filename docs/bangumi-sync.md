# Bangumi 双向自动同步

## 连接账号

在「设置 → Bangumi 同步」打开官方个人令牌页面，创建有收藏写入权限的个人访问令牌，粘贴到密码输入框，点击「验证并保存连接」。验证请求只读取账号信息；通过后令牌存入当前 Windows 用户的凭据管理器，自动同步保持关闭。

账号令牌不保存在 SQLite、普通设置、JSON 导出、日志或完整备份内。界面不读取保存的令牌。更换令牌后需要重新开启自动同步，断开连接会删除本机保存的令牌。令牌失效或权限不足时自动同步暂停，设置显示原因。

## 设置每款作品

在游戏详情的基本信息页下方找到「Bangumi 个人记录与同步」：

- 填写正确的 Bangumi 游戏条目数字 ID，启用本款同步。新绑定会校验条目类型。
- 「我的评分」为 0–10 整数，0 表示未评分。它与作品资料里的公共评分分开保存。
- 「Bangumi 短评」为用于同步的个人评价，与私人备注分开保存。新编辑短评上限 1000 字。
- 保存个人记录后，再到设置开启「双向自动同步」。未绑定作品不会按名称自动匹配，远端独有作品不会自动创建本地条目。

## 自动同步规则

应用运行期间，通常每 120 秒比较一次已绑定作品；保存状态或个人字段后尽快触发（运行器约每 10 秒检查）。启动游戏使状态变为游玩中时也会触发。断网或关闭应用期间不执行同步，后续按本地保存的记录重新比较。设置里的「立即双向同步」即使自动开关关闭，也会执行一次读写同步。

| 恋页状态 | Bangumi 收藏类型 |
|---|---|
| 未游玩 | 想看 / 想玩（1），本地保留未游玩 |
| 想玩 | 想看 / 想玩（1） |
| 已通关 | 看过 / 玩过（2） |
| 游玩中 | 在看 / 在玩（3） |
| 搁置 | 搁置（4） |
| 弃坑 | 抛弃（5） |

未游玩按 Bangumi「想玩」同步：远端没有收藏时自动创建，本地仍保留未游玩。已绑定且启用同步才参与处理；暂停或未绑定作品继续跳过。首次同步两边状态不同时仍需处理冲突，已有远端进度不会直接被覆盖。

同步字段为已保存的状态、我的评分和 Bangumi 短评。公共评分、私人备注、资料标签、路径、存档及游玩时长不会上传。已有远端收藏的标签和隐私保持原样；新建收藏默认仅自己可见，可在设置调整。

## 冲突与失败

每款作品保存最后一次成功同步的基线，按字段比较本地、远端和基线。只有一边变更时自动传播；两边同样变更直接确认；同一字段两边改成不同内容时，显示冲突。首次同步两边有不同的有效内容，也会要求处理，换账号时不会丢弃本地个人记录。

「保留本地」「采用 Bangumi」只决定冲突字段，其余非冲突字段继续正常合并。远端收藏被移除时不会自动重建；明确保留本地可重新创建，采用远端则将本地设为未游玩、清空对应个人收藏字段并暂停本款同步，避免下一次又按想玩重建。也可以直接暂停本款同步。

上传前后会读取远端复核；同步期间修改的本地记录由版本检查保护。暂停只修改开关，不回写旧界面里的评分或短评。远端复核与写入是独立请求，若同时在网页编辑同一内容，仍需留意后续差异提示。网络失败不推进成功基线，下一次重新比较；限流不立即重试。

Bangumi 官方注明收藏的 `updated_at` 不适合作为所有修改的可靠时间，所以本实现不按该时间直接覆盖。[官方收藏结构](https://github.com/bangumi/server/blob/master/openapi/components/user_subject_collection.yaml)、[修改字段定义](https://github.com/bangumi/server/blob/master/openapi/components/user_subject_collection_modify_payload.yaml)。

## 备份与范围

完整备份包含个人记录与同步基线，不含令牌。普通游戏条目 JSON/CSV 仍只导出其原有字段；迁移个人同步记录请使用完整备份。恢复备份后自动同步关闭，确认账号后重新开启。

首版只同步本地已绑定作品，没有自动导入整份 Bangumi 收藏列表、标签同步或路线/游戏时长同步。
