# 完整备份与恢复

设置 → 数据管理 → 完整备份与恢复可导出 `.koibak` 文件。归档包含 SQLite 的 `VACUUM INTO` 一致性快照、数据库实际引用的封面、生日头像及自定义头像、本地背景；不包含游戏本体与游戏存档。相同图片引用只存一次。图片缺失或解码失败会阻止导出，避免生成不完整备份。当前限制为归档 1 GB、单张图片 32 MB。

恢复先检查格式版本、数据库迁移版本及已登记迁移的 SHA-384、每项 SHA-256、图片解码、SQLite 完整性与外键、游戏和游玩记录计数及图片引用是否完整，再显示预览。数据库必须包含必要数据表，不接受触发器或视图。自定义封面 `game_cover:<id>` 设置里的 `customPath` 同样备份和重映射，并保留封面遮挡等其他设置。用户必须勾选覆盖确认；确认时重新验证归档内容，阻止预览之后被替换的文件。备份和恢复均持有游戏启动锁，运行游戏时拒绝操作。

准备恢复前，当前数据库与图片会另存为应用配置目录下的 `before-restore-*.koibak`。所有图片复制到应用数据目录下独立的 `restored-assets/<编号>`，数据库内的绝对路径随之替换，支持在不同设备/用户目录中恢复。数据库改写发生在暂存副本，运行中的数据库不被替换。

准备完成后需完全退出恋页（包含托盘）并重新启动。启动恢复插件必须注册在 SQL 插件之前。它先验证暂存数据库、回退快照及所有图片的校验值，保留原数据库与 WAL/SHM，再用重命名切换新数据库；中断后根据磁盘暂存状态重试。发生切换失败时，从独立的一致性快照回退，失败暂存内容保留为 `restore-failed-*`；设置里的完整备份区域会显示失败原因。原数据库、回退快照和完成记录保留在配置目录的 `restore-completed-*`，不会自动删除安全备份。只有无法验证回退快照且原库已经不可用时才停止启动，避免创建空数据库。准备后至重启前的编辑不包含在待恢复数据中，因此应立即退出。

格式无需 ZIP 或外部程序：ASCII `KOIPAGE-BACKUP-1\n`，接 8 字节小端 JSON 清单长度、UTF-8 JSON 清单、按清单顺序拼接的原始载荷。第一项固定为 `database.sqlite`，其余项位于 `assets/`。清单记录格式版本、应用版本、迁移版本、创建时间、计数、每项大小/原路径/SHA-256。解析器拒绝绝对路径、冒号、反斜杠、空路径段、`.`/`..`、重复路径/来源、超限长度、尾随数据和未来版本。SHA-256 用于损坏检查，不提供签名认证；备份含完整个人库与设置，应妥善保存。

验证测试使用临时 SQLite、临时文件与单独标识的 QA 应用目录，不读写实际用户游戏库。

Windows 加密属性的目录上，文件或目录即使位于同一目录，也可能返回 `ERROR_NOT_SAME_DEVICE`。文件先使用标准重命名，仅对此错误退回 `MoveFileExW` 的 `COPY_ALLOWED | REPLACE_EXISTING | WRITE_THROUGH`；源文件在完整复制成功后才删除。此回退不承诺原子性，所以恢复日志始终保留一致性回退快照，启动时验证暂存源以及已经完成移动的目标；若中断留下部分目标但源仍在，会从已验证源重试。封面缓存同样使用此文件移动函数，既有缓存字节不符时会重新发布。

目录回退仅用于备份模块自己创建的平面暂存目录，不递归移动用户目录：逐项复制并同步文件，最后才发布 `ready` 标记；发布完成后先移除旧标记，避免清理中断导致重复恢复。未发布 `ready` 的固定暂存目录在下次启动清理。可设置 `KOIPAGE_TEST_ENCRYPTED_ROOT` 为隔离 QA 目录，对完整恢复、文件移动和封面缓存进行带加密属性目录的回归测试；所有测试仍创建自己的唯一子目录。
