# 游戏归档与存档备份实施计划

目标：支持本体已卸载但保留全部管理记录，以及真正的游戏存档备份与恢复。

实现沿用 React、Tauri/Rust、SQLite 设置表；不改变现有游戏游玩状态枚举，不修改既有迁移。归档标记与备份策略随设置持久化；实际存档快照保存在独立的本地备份目录，不混入原有数据库/封面 `.koibak`。

- [x] 归档：设置表标记，运行时拒绝归档；恢复安装状态前核验路径。详情入口、库卡片/行状态和可保存的筛选；路径检查识别已卸载并跳过默认修复。
- [x] 存档快照：每游戏指定文件或目录，手动及启动前/正常退出后备份。自动策略默认关闭，自动快照限额，手动和恢复前安全备份保留。
- [x] 恢复：清单/内容哈希校验、拒绝符号链接和路径穿越、操作互斥、运行中禁止恢复。覆盖前保存当前存档，使用分阶段替换和失败回滚，反馈成功或失败。
- [x] 详情 UI：目录/文件选择、策略、历史快照列表、打开备份目录、恢复/删除确认；长页面中的弹窗必须显示在视口。
- [x] 启动集成：归档游戏后端拒绝启动；启动前备份失败明确阻止启动；正常退出先结算时间，再备份并发送完成/失败事件。
- [x] 验证：偏好与持久化单元测试，真实目录快照、篡改、恢复、安全备份、限额及错误路径测试；前端类型/构建/IPC/测试；独立 app identifier 的 WebView 验证。保留用户现有未提交改动，无发布安装包。

并行边界：归档 agent 负责 installation/库/路径检查；备份后端 agent 负责新 Rust 模块；备份前端 agent 负责独立面板；主代理负责注册、启动生命周期、详情集成及联合验证。
