# 可靠性与整理效率（开发版）

## 行为

- 重新匹配资料默认仅勾选空字段，并展示当前值；用户可逐字段明确勾选覆盖。「全选」会覆盖已有字段，界面明确提示。自动补全仅填空字段、合并标签、保留已有封面；评分 0 也受保护。
- 一键导入保留当前窗口的任务状态，支持重试全部失败项、单项重试，以及继续停止后尚未开始的项目。已成功入库条目不会重跑，模糊匹配仍由人工确认。关闭窗口后不持久化任务队列。
- 设置的数据管理增加「迁移到新电脑」向导，可校验预览数量和容量，并选择把已创建的存档快照纳入 `.koibak`。旧格式可读取，普通备份仍使用旧清单结构。迁入后快照保存到独立本机目录，不直接替换实际存档。归档上限仍为 1 GB。
- 游戏库网格与列表首次显示最多 120 项，通过「加载更多」继续显示；筛选、搜索和批量全选覆盖全部匹配结果，返回详情前的已展开数量得到保留。此实现是分批显示，不是虚拟列表；主动加载全部后仍会挂载全部卡片。

## 大库测量

在 Windows WebView2 / Edge 156 开发环境中，用 `node scripts/cdp-eval.mjs --file scripts/benchmark-library.js` 测量真实 GameCard 组件。合成数据仅存在临时 DOM，不写入游戏库。先预热 100 张卡片，再分别测量全量与首批挂载。

| 合成收藏量 | 一次挂载全部 | 首批 120 项 |
|---|---:|---:|
| 1000 | 129.8 ms | 10.0 ms |
| 5000 | 633.7 ms | 11.1 ms |
| 10000 | 1123.9 ms | 12.5 ms |

这是单次开发环境组件挂载测量，不含数据库读取、封面解码和首次模块加载，不能等同于完整页面加载速度。后续如需优化全量加载后的滚动，仍应结合真实图库做虚拟化和缩略图评估。

补充隔离浏览器交互验证的启动被工具策略阻止，未继续尝试该方式。交付依据为前后端自动化测试、现有开发版窗口验证和原生导出/预览校验。

一次补充界面测试未能替换原生 IPC（该对象属性不可写），导致实际库中新增两条专用路径为 `synthetic/A`、`synthetic/C` 的测试记录。已仅删除这两条记录、新增的 5 个标签及两张测试封面；逐表与测试前的 SQLite 检查点比对，所有业务表记录完全一致（内部自增 ID 计数不回退）。未使用整库恢复。清理后的 17 部收藏再次完成原生迁移导出与预览校验。后续不得在原生窗口尝试此类 IPC 替换测试，应使用独立测试环境。
